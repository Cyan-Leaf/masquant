# 复现与改进 · 使用说明

本目录基于 [MASQuant](https://github.com/alibaba/EfficientAI) 官方代码，做了复现、修复和三个拓展。
文档见 `docs/`，本节只讲**怎么跑**。

## 环境

```bash
# 仓库要求 transformers 4.52，全局环境若为 4.57 会因 API 变更无法导入模型
python -m venv --system-site-packages /path/to/venv
/path/to/venv/bin/pip install "transformers==4.52.0" termcolor texttable more_itertools pypdf
/path/to/venv/bin/pip install lmms-eval==0.4.0 qwen-omni-utils qwen-vl-utils moviepy librosa soundfile decord
```

## 数据准备

```bash
export MASQUANT_DATA_ROOT=/path/to/masquant/data

# 1) 模型权重（走 ModelScope 更快；hf-mirror 的 LFS 会限流）

#    data/wikitext/{train,test,validation}-00000-of-00001.parquet

python tools/make_videos.py
```

## 复现主流程

```bash
export inference_mode=split_scales      # 必须！否则 MAS 白训

# Step 1: 统计分模态激活尺度
python generate_act_scale_shift.py \
  --model $MODEL --dataset-type text-vision --nsamples 128

# Step 2: 训练 MAS 并评 PPL
python main.py --model $MODEL --mode train --epochs 2 --wbits 4 --abits 8 \
  --let --loss_multi_modal_mae_alpha --dataset-type text-vision --nsamples 128 \
  --symmetric --group_size 0 --eval_ppl --output_dir ./outputs_vl/w4a8

# Step 3: 多模态 benchmark（脚本里已封装各 baseline）
LIMIT=0.03 TASKS=scienceqa_img,textvqa_val bash scripts/launch_all_bench.sh

# Step 4: CMC（低秩补偿）
python infer_mas.py --mode infer --model $MODEL --net qwen2.5-vl-3b \
  --scales_path outputs_vl/w4a8/*/mas_parameters.pth \
  --wbits 4 --abits 8 --LR --quantize --n_cali_samples 32 \
  --cali_data_type vision-audio-only --rank 0.05 --quant_cmc 0 --eval_ppl
```

## 改进项的开关

| 改进 | 用法 |
|---|---|
| **NVFP4 量化** | `--wfmt nvfp4 --afmt nvfp4 --wbits 4 --abits 4` |
| **自适应 rank（CMC）** | `infer_mas.py --adaptive_rank greedy --rank 0.05 --rank_min 32 --rank_cap 0.05`（`energy` 为另一种策略） |
| **视频模态** | `--dataset-type text-vision-video`；视频默认与图像共享尺度，设 `MAS_VIDEO_SHARE_VISION=0` 可关闭 |
| **SQNR 探针** | `python tools/snr_probe.py --model $MODEL --scales <mas_parameters.pth> --data-type text-vision-video --nsamples 4 --layer-step 9` |

## 新增/修改的文件

**新增**
- `quantize/nvfp4.py` — NVFP4（E2M1 + FP8 块缩放）伪量化
- `quantize/rank_alloc.py` — CMC 的按层自适应 rank 分配
- `tools/snr_probe.py` — 按模态统计 SQNR 的轻量探针（复现论文 Fig.2）
- `tools/msdl.py` / `tools/hfds.py` — 模型与数据集的并发下载
- `tools/make_videos.py` — 由 COCO 图像合成视频校准集
- `tools/localize_lmms_tasks.py` — 把 lmms-eval 任务改为读本地 parquet
- `scripts/run_ppl_baselines.sh` / `scripts/run_bench.sh` / `scripts/launch_all_bench.sh`

**修改（相对官方代码）**
- `custom_dataset.py` — 去掉硬编码的 `/nas/yuehu/...`，改走 `MASQUANT_DATA_ROOT`；新增 `text-vision-video`
- `datautils.py` — wikitext2 支持本地 parquet（离线）
- `generate_act_scale_shift.py` — 支持视频 token 的激活统计
- `quantize/int_linear.py` — `QuantLinear` 增加 video 分支；抽象出 `build_quantizer` 以支持 NVFP4
- `quantize/masquant.py` — video 尺度的初始化与 loss；视频与图像共享尺度的策略
- `quantize/svd_utils.py` — 支持按层指定 rank
- `models/modeling_qwen2_5_vl.py` — 把 `video_mask` 透传给 LLM
- `models/LMMClass.py` — 可配置 batch size / max_pixels / padding_side（评测吞吐）
- `main.py` — 新增 `--wfmt/--afmt`；lmms_eval 缺失时降级而非崩溃
- `infer_mas.py` — 新增 `--adaptive_rank/--rank_min/--rank_cap`

## 已知限制

- MMMU 需要 OpenAI 作为 judge，未纳入评测
- OCRBench 的 `submission` 聚合需要 `output_path`，在 main.py 的调用路径下拿不到，未纳入
- fp16 路径的 SDPA 与量化路径的 eager 实现对 `batch>1` + 2D mask 行为不一致，benchmark 统一用 `batch=1`
- CMC 的收益在纯文本 PPL 上不可见（视觉旁路不激活），需要用多模态 benchmark 评估

## 新增的开关与脚本（第二轮迭代）

### 环境变量
| 变量 | 默认 | 作用 |
|---|---|---|
| `inference_mode` | merged_scales | **训练 MAS 必须设 `split_scales`** |
| `MAS_FAST` | 1 | 按模态 gather 的单遍前向（prefill 3.84×、decode 9.24×，数值等价） |
| `MAS_WQ_CACHE` | 1 | no-grad 时缓存量化后的权重 |
| `MAS_VIDEO_SHARE_VISION` | 1 | 视频 token 复用图像平滑尺度（推荐开启，见报告 §5.3） |
| `MAS_VISION_GRAD` | — | 覆盖视觉 loss 权重（代码默认 0.5） |
| `MAS_NO_CMC` | 0 | 消融：CMC 推理时不做低秩补偿 |
| `MAS_DETERMINISTIC` | 0 | 可复现模式。**只用于排查，不要用来报数**（强制 math SDPA，结果系统性偏差） |
| `LMMS_EVAL_BATCH_SIZE` | 1 | 评测 batch（>1 时 fp16 路径的 SDPA 与量化路径的 eager 对 2D mask 行为不一致，建议保持 1） |
| `LMMS_MAX_PIXELS` | 0 | 限制视觉 token 数（401408 ≈ 0.4MP，评测提速 4×） |

### 新增数据集类型
- `text-vision-video`：图像 + 视频 + 文本（视频由 `tools/make_videos.py` 合成）
- `text-vision-mix`：图像描述 + wikitext 纯文本，比例由 `MAS_CALI_TEXT_RATIO` 控制（默认 0.5）。
  **推荐 0.5（默认值）**。0.75 在 wikitext 上略好（16.19 vs 16.35）但跨到 C4 领域后优势消失
  （报告 §2.1.3），两者差异在两个测试集上都不显著，用默认的 0.5 即可，省去额外生成 act_scales。
  注：曲线在 0.375~0.875 是宽平台，不必精调；且 `act_scales` 要与训练时的比例匹配（路径会自动带上 `_tr0.75`）。
  ```bash
  MAS_CALI_TEXT_RATIO=0.75 python main.py ... --dataset-type text-vision-mix --nsamples 128
  ```
  注意：不同比例有各自的 dataloader 缓存（文件名含 `_tr0.75`），不会串用。

### 分析工具
```bash
# 按模态统计 SQNR（复现论文 Fig.2），秒级出结果
#   --measure output（默认）：量化激活 + 量化权重，量线性层输出（对应论文 Theorem 1）
#   --measure act          ：只量化激活（旧口径，仅用于和历史数字对照）
#   --modes: rtn | mas | uniform | vision
python tools/snr_probe.py --model $MODEL --scales <mas_parameters.pth> \
    --data-type text-vision-video --nsamples 4 --layer-step 9 \
    --modes rtn,mas,uniform --out outputs/snr.json

# 无标签保真度：相对 FP16 的 KL 与 top-1 一致率，按模态分组
# --modes: fp16 | uniform | mas | cmc
#   uniform : train 路径 + merged_scales，所有 token 用文本尺度（≡ "统一 scale"）
#   mas     : train 路径 + split_scales，各模态用各自尺度
#   cmc     : infer 路径（mode=infer + MAS_NO_CMC=1），即 infer_mas.py 的"无补偿"
#             uniform 与 cmc 数值逐位相同，可用于互相验证
python tools/fidelity_eval.py --model $MODEL --mas <mas_parameters.pth> \
    --modes uniform,mas --data-type text-vision-video --compare-type text-vision \
    --nsamples 8 --out outputs/fidelity.json

# 配对 bootstrap（读 main.py 落盘的 samples_*.jsonl）
python tools/paired_bootstrap.py --runs fp16=outputs_bench/fp16 mas=outputs_bench/mas \
    --tasks scienceqa_img textvqa_val --ref fp16

# 快路径数值等价性 + 测速
python tools/test_fast_forward.py
```

### 复现实验的注意点
1. **每个训练配置至少跑 3 次**：训练路径存在 kernel 层面的非确定性，单次 PPL 可差 2.9（报告 §1.2）。
2. **不要用 `--limit` 评 PPL**（它 break 了样本循环但分母没变），只用于 benchmark。
3. benchmark 会落盘逐样本结果（`samples_*.jsonl`），务必用配对 bootstrap 而不是只看均值。
4. CMC 在纯文本 PPL 上三组完全相同，**必须用多模态 benchmark 评估**。
