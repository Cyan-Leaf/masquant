## 0. 上台前必须知道的四件事

### 0.1 一句话主线（全场只讲这一条线）

> **论文的动机是对的，但归因错了。**
> 「分模态平滑」本身不带来增益；真正有效的是 **校准数据的模态平衡**（零成本）
> 和 **把量化真正能动的那两个自由度用好**（下游 +7.5）。
> 而这两件事是串联的：不先修校准集，更强的方法反而有害。

这条线有三个优点：有转折（不是流水账）、有因果（A → F）、有落点（给出一个更简单的部署方案），
正好对应评分表里的「逻辑性」和「完成情况」。

1. **不复述 p 值和置信区间**。被追问就用一句「所有差异都是同题配对检验，看区间有没有跨零」，

### P2 · 背景（45s）

**页面**：左边一张对比图（视觉 token 与文本 token 的激活绝对值分布，**对数轴**，两条曲线错开 1~2 个数量级）；
右边三行字：`PTQ` / `SmoothQuant = 逐通道缩放，把离群值从激活搬到权重` / `多模态：一套缩放只能迁就一边`。

> 没有现成图就用 `fig4_sqnr.png`，或直接把「10–100×」放到最大字号。**不要为这张图重画。**

**口播**：

> 先说量化，一句话：把模型里的权重和激活从 fp16 压到 4 bit，模型小四倍，代价是掉点。
> 难在激活里有离群通道——某一维比其它维大几百倍，一行只有一个量化步长，被它撑大后其余全被压成 0。
> SmoothQuant 是这条线的标准做法：用逐通道缩放把离群值从激活「搬」到权重上，数学上是恒等变换，量化之后才有区别。
> 多模态的问题在于，**视觉 token 的激活比文本大一到两个数量级**。一套缩放只能迁就一边：跟着视觉走，文本被压坏；跟着文本走，视觉撑爆步长。论文管这个叫「平滑错位」。

**任务**：45 秒内让所有人（包括没接触过量化的）明白「为什么多模态量化和纯文本量化不是一个问题」。
**这里不解释**：per-token / per-channel、量化误差公式、为什么是 4 bit。

### P3 · 论文两招（40s）

**页面**：左边 MAS（每个模态一套 $s_m$，闭式解初始化 → 逐层训练最小化重建误差）；
右边 CMC（只存文本的 $Q(S_tW)$，其它模态加低秩旁路）。
右下角小红框：`我们发现的笔误：定理 1 的分子分母写反`。

**口播**：

> 论文两个招。第一招 **MAS**：每个模态各有一套平滑因子，用本模态自己的数据初始化，然后逐层训练，让量化前后这一层的输出尽量接近。
> 第二招 **CMC** 解决一个副作用：分模态意味着每个模态都要存一份 4 bit 权重，显存翻三倍，压缩就没意义了。所以只存文本那一份，其它模态加一条低秩旁路补差。
> 我们精读时还发现论文定理 1 的**公式分子分母写反了**。检验很简单：各模态量级完全一样时，错位损失应该是 0，按原式算不是 0。

**任务**：40 秒讲完两个方法 + 一个加分点。笔误只说这一句，**不要展开推导**（追问再讲，见 Q3）。

### P5 · 核心发现：归因错了（50s）★

**页面**：一张只有三行的表，右边配一句结论。

| 配置（除「平滑方式」外全部相同） | ScienceQA | TextVQA |
|---|---|---|
| MAS（每个模态一套） | 78.65 | 63.47 |
| 统一一套（同校准、同初始化、同训练） | 78.70 | 64.39 |
| 差异 | 打平 | 打平 |

页脚小字：`PPL 上同样打平（p=0.97）` + `音频 ASR 上同样打平（6.58 vs 6.58，p=0.999）`。

**口播**：

> 那接下来要问的是：**MAS 比 SmoothQuant 高的这 3 点多，到底是哪儿来的？**
> 论文的答案是「因为每个模态各学一套尺度」，也就是说增益来自「**分模态**」这个设计。
>
> 我们想直接验证这个归因，办法是把这个设计换掉、**其它一个都不许动**：给一套统一的缩放，但用同样的校准数据、同样的初始化、同样训练两轮。
> 结果是 78.70 对 78.65，差 0.05；TextVQA 上统一那边甚至高 0.9 点——什么都没变。
>
> 这一条我们还**换了个模态复核**：论文最硬的证据其实在音频，我们就在 Omni 上跑了一整套 ASR。
> 统一一套 6.58，分模态也是 6.58，p 等于 0.999——两个模态、两个模型，都是打平。
>
> 所以结论不是论文错了，是**归因错了**：那 3 点多来自「从固定的公式变成可学习」这一步，而不是「分开学」这个结构。

**任务**：全场第一个高点。技巧是**先复述论文的答案**（「论文说是分模态」），再给反证——
这样听众知道你在驳什么，而不是听一个孤立的「打平」。

### P7 · 改进 F：量化只有两个旋钮（155s）★★ 全场最高点

**页面**：一页，从上到下四层。

**第 1 层（标题行）**：
`量化一层权重，只有两个可以动的地方`

**第 2 层（本页骨架，左右两栏）**：

```
   ① 步长 scale                      ② 码字 code
   这一行用多大的格距                 每个权重落在哪个格点上

   默认：absmax / 7                   默认：就近取整（RTN）
        「最大值必须无损」
        ↓                                  ↓
   ┌─ clip（削顶）─┐                  ┌─ GPTQ（误差反馈）─┐
   │  γ·absmax/7   │                  │  误差扩散抖动      │
   └───────────────┘                  └────────┬──────────┘
                                        ↓
                                  ┌─ cd（坐标下降）─┐
                                  │   → 1-opt       │
                                  └─────────────────┘
```

**第 3 层（台阶，贴在右栏下方作注）**：
`RTN 完全不协同 → GPTQ 贪心（定完不回头）→ +cd 达 1-opt（单独改任何一个都不再更好）`
`本质：离散二次规划 · NP-hard`

**第 4 层（结果条）**：
`TextVQA 63.5 → 71.0（+7.5）· 与 FP16 差 12.4 → 4.0 · 格式不变、推理零开销`

**口播（按这个顺序，这是全稿最重要的一段）**：

> 下游收益最大的改进是这个。我先把它拆简单一点。
>
> **量化一层权重，其实只有两个地方可以动**：一个是**步长**，这一行用多大的格距；另一个是**码字**，每个权重最终落在哪个格点上。
> 论文的平滑改的是「输入怎么缩放」，等于换了个坐标系——但这两个旋钮它一个都没碰：步长还是「这一行最大值除以七」，码字还是逐个就近取整，也就是 RTN。所以我们一个旋钮一个旋钮来用。
>
> 先说**码字**这一侧，因为这里有一个很清楚的算法结构。4 bit 只有十六个可表示的取值，把每个权重放到其中一个上、让这一层的输出误差最小——这是个**离散二次规划**，NP-hard，没有精确解。所以只能比「局部到什么程度」：
> **RTN** 各自就近取整，谁也不管谁，完全不协同。
> **GPTQ** 强得多：一列一列地量化，把每列舍入产生的误差补偿给后面还没量的列——就是图像里的**误差扩散抖动**，只是扩散核换成了从数据统计出来的逆 Hessian。但它是贪心，定完一列不回头。
> 我们加的第三级 **cd，坐标下降**：GPTQ 解完之后逐个元素来一遍，固定其它所有元素，单独把这一权重在十六个格点里重选，只接受让误差下降的改动。扫到收敛就达到 **1-opt**：单独改任何一个，都不可能更好。
> 再往上、同时改两个，组合代价高、收益不划算，我们停在 1-opt。
>
> 再说**步长**这一侧。默认的「最大值除以七」要求这一行最大的那个值必须无损，代价是为了一个值把整行格距撑粗。我们让最大值轻微削顶，换大多数元素更细的格距——**一行上千个元素，一个亏、其余赚**。而且它和 GPTQ 互补：只削顶、不做 GPTQ，它自己就有收益；加上 GPTQ 还能再降一截。
>
> 所以两个旋钮各有各的工具：**步长交给 clip，码字交给 GPTQ 加 cd。**
>
> 结果是 TextVQA 从 63.5 到 71.0，涨 7.5 点；与 FP16 的差距从 12 点缩到 4 点。格式没变、推理零开销。
>
> 最后还有一个多模态特有的前提，也是整条线的收口：**这一整套要求校准集已经修好。** 在原校准集上，同样的 GPTQ 让 9 个 checkpoint 全部变差——不先修校准集，更强的方法反而有害。

**任务**：全场唯一需要「讲透」的地方。
**取胜点**：先用「只有两个自由度」把问题框住，再在码字那一侧展开算法台阶。
这样即使听众没听过 GPTQ，也能听懂「这是个 NP-hard 的离散优化，不同方法只是局部最优的深度不同」。
**允许超 10 秒，但绝不允许加第 5 个方法。**

### P8 · 其余三条（40s，只列不展开）

**页面**：三行清单，每行一句话 + 一个数字。**不要出现表格以外的东西。**

- `CMC（论文的低秩补偿）：补 4000 题下游 → 论文默认配置 TextVQA −6.9；不加旁路反而最好`
- `NVFP4 W4A4：INT4 直接崩，FP4 块缩放 → ScienceQA 与 FP16 无差异；同是 4bit 权重比 INT 高 10 点`
- `工程：修 7 个 bug；按模态 gather 的单遍前向，prefill 3.8× / decode 9.2×，输出逐位一致`
- `视频模态 / W4A6 下游 / 可复现性诊断：详见书面报告`

**口播**：

> 剩下三条一句话带过。
> 论文另一个核心机制 CMC，也就是低秩补偿，我们补了 4000 题下游：论文默认配置让 TextVQA 掉 6.9 点；而**不加任何旁路、所有 token 只用文本尺度，反而和理想上界打平**。

## 4. 四个难点的具体讲法

### 4.1 什么是量化（20 秒，P2 开头）

> 「把权重和激活从 fp16 压到 4 bit，模型小四倍，代价是掉点。难在激活里有离群通道。」

**只讲结论，不讲**：量化误差怎么算、per-token 和 per-channel 的区别、为什么选 4 bit、有没有硬件支持。
被追问一句话：「权重按每个输出通道一个步长，激活按每个 token 一个步长，是这套方法的标准配置。」

### 4.2 MASQuant 与 SmoothQuant 的关系（15 秒，P2 中段）

> 「MASQuant 可以理解成 **SmoothQuant 的多模态版**：SmoothQuant 用一套缩放，MASQuant 给每个模态各一套，多出来的权重用低秩旁路省掉。」

**为什么这样讲最好**：听过 SmoothQuant 的人这一句就定位完了；没听过的也能听懂「一套 vs 多套」。
**不要讲**：$\beta=0.5$ 的闭式解、为什么用 L1 loss、为什么 down_proj 不平滑。

### 4.3 两个自由度（P7 全场骨架）

**这一层的作用**：在讲任何方法之前，先给听众一个"容器"——让他们知道后面出现的所有东西各自装在哪里。
没有这个容器，clip 和 cd 就是两个孤立的技巧；有了它，两个改进各就各位，而且逻辑闭合。

| 自由度 | 是什么 | 默认怎么定 | 我们换成什么 |
|---|---|---|---|
| **步长 scale** | 这一行（输出通道）用多大的格距 | $\max|w|/7$，隐含「最大值必须无损」 | **clip**：$\gamma\cdot\max|w|/7$，削顶换细格距 |
| **码字 code** | 每个权重最终落在哪个格点上 | 就近取整（RTN） | **GPTQ**（误差反馈）＋ **cd**（坐标下降 → 1-opt） |

**必须点出的一句话**（它是整页的立论点）：

> 「论文的平滑改的是『输入怎么缩放』，等于换了个坐标系——但这两个旋钮它一个都没碰。」

这句话让听众立刻明白：论文和我们不是同一个层面上的竞争，我们是在它下面一层动手。

### 4.4 码字侧：算法台阶（P7 右栏，约 90 秒）

| 台阶 | 一句话 | 说明什么 |
|---|---|---|
| 问题 | 4 bit 只有十六个取值，把每个权重放到其中一个上、让层输出误差最小 —— **离散二次规划，NP-hard** | 精确解不存在，只能比「局部到什么程度」 |
| RTN | 各自就近取整，谁也不管谁 | 完全不协同 |
| GPTQ | 逐列量化 + 误差反馈（**误差扩散抖动**） | 强得多，但是贪心，定完不回头 |
| **GPTQ + cd** | 逐元素重选码字；固定其它变量时可闭式求最优 | **1-opt：单独改任何一个都不再更好** |
| 2-opt | 同时改两个，能跳出 1-opt 的坑 | 组合代价高；**本项目未实现**，我们停在 1-opt |

**落点必须说这一句**（它把「cd 没有端到端收益」变成正面结论）：

> 「理论上还能再往上走——同时改两个——但组合代价高、收益不划算，我们停在 1-opt。」

**千万别做的事**：把 cd 讲成「我们试了一个新算法，效果一般」。
正确说法是「**我们用算法视角把这个问题的结构讲清楚了：RTN 到 GPTQ 是质变，GPTQ 到 1-opt 是收尾，再往上就不值了**」。

### 4.5 步长侧：clip（P7 左栏，约 35 秒）

三句话，语速可以快：

> 默认步长要求「最大值必须无损」，为了一个值把整行格距撑粗 → 削顶换细格距 → **一行上千个元素，一个亏、其余赚**；只削顶不做 GPTQ，它自己就有收益，加上 GPTQ 还能再降一截。

**如果被问「为什么不是反过来，只做 GPTQ」**：只做 GPTQ 时 TextVQA 到 70.9，加 clip 到 71.0，两列数字都在手卡上；
而 **ScienceQA 上 clip 的贡献更明显**（不平滑时 GPTQ 单独 76.1，加 clip 回到 78.7）。

### 4.6 「GPTQ 不是已有方法吗」的标准答法（一定被问）

> 「GPTQ 是现成方法，我们没改它的内核；cd 和 clip 也都是经典的离散优化手段，各自都不新。
> 这个改进的价值在**框架和前提**上：一是先把量化拆成『只有步长和码字两个自由度』，说清论文的平滑这两个都没碰，
> 于是两个旋钮各配一个工具；二是**多模态特有的三个设计问题**——Hessian 在哪个空间统计、用哪些 token、校准集要满足什么条件。
> 第三个问题给出了一个反直觉的结论：在原校准集上，同样的 GPTQ 让 9 个 checkpoint 全部变差。」

> 原则：**先给一句话结论（加粗那句），对方追问再展开。** 每题 25 秒内。

| # | 问题 | 一句话答案 |
|---|---|---|
| Q1 | **既然分模态没用，论文是不是错了？** | **不是动机错了，是归因错了**：视觉离群值污染其它模态这个现象我们复现了（音频上同样：SQ 直接崩，MAS 只差 1 点）；但给统一平滑同样的校准和训练后两者打平（VL $p=0.97$、音频 $p=0.999$），增益来自「从闭式解变成可学习」。 |
| Q2 | **不显著不等于没差异，样本够吗？** | **够**：SQA 上的差异区间是 $[-1.35,+1.25]$ 个百分点，能排除 1.3 点以上的差异；PPL 每侧 3~14 次重复。 |
| Q3 | **定理 1 凭什么说写反了？** | **检验极端情况**：各模态量级一样时错位损失应为 0；按原式不为 0。按论文自己的推导重推，分子分母要互换。 |
| Q4 | **GPTQ 不是已有方法吗？创新在哪？** | 见 §4.6。**两个自由度的框架 + 三个多模态设计问题 + 反直觉结论（原校准上 9/9 更差）。** |
| Q5 | **为什么只用 3B？** | **官方示例脚本默认就是 3B**。3B 单卡一轮 5~7 分钟，我们才能做一百多次独立训练来支撑重复与显著性检验；7B 会降到十几次，做不了检验。代价是外推受限，写在局限里。 |
| Q6 | **为什么只有两个 benchmark？** | **评测链路限制**：MMMU 需要外部 judge，OCRBench 的聚合指标在现有调用路径下拿不到。**我们选的是「两个但全量 + 配对检验」，不是「多但只跑 10%」。** |
